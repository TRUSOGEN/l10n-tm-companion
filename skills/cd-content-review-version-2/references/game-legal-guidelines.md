# LIVE Journey: Content Strategy & Writing Guidelines

---

# Product at a glance

## Summary

LIVE Journey is a cyclical, gamified incentive container for TikTok's **non-e-commerce LIVE creators** — a "do tasks → earn rewards" loop that creators self-compete inside.

Each season, creators progress through **stages** by completing **weekly and seasonal challenges** spanning broadcast time, audience engagement, monetization, feature adoption, and short-video operations. Stage progression unlocks a **multi-track reward pool** — traffic boosters (flares, Promote coupons), honor & visual collectibles (stickers, Hall of Fame), monetary rewards (Diamonds), and gameplay items (quickpasses, multipliers). The product is surfaced across **pre-LIVE, in-LIVE, post-LIVE, and async** touchpoints, with the goal of building **a high-penetration, low-interruption, emotionally engaging space** that sustains creators' sense of achievement and "flow" — and, through it, nudges adoption of adjacent LIVE tools.

## Business goals & How to achieve them

| Goals | Tools |
|-------|-------|
| **Drive broad participation:** Reach as many eligible non-e-commerce creators as possible with a personalized, low-friction entry. | - Multi-surface entry points<br>- Main container (central hub)<br>- Personalization platform |
| **Drive consistent and higher-quality broadcasts:** Use achievable, varied challenges + timely positive feedback to keep creators broadcasting more, longer, and across more skills. | - Weekly and seasonal challenges<br>- Multi-track task pool<br>- Stage-up and end-LIVE celebrations |
| **Keep incentives healthy and cross-leveraged:** Make rewards transparent and route them so they fuel both creator growth and adjacent LIVE tools (Promote, Campaigns, LIP, Service+, Playbooks, LIVE Academy). | - Multi-track reward pool<br>- Real-time center + Reward list/details<br>- Cross-feature reward routing |

## User goals

**LIVE creators:**
- **Understand what to do next** to grow on LIVE.
- **Feel a sense of progress** and achievement.
- **Unlock useful tools and perks** that help them create better content.

**Viewers:**
- **Enjoy more consistent and engaging content** from their favorite creators.
- **Participate in a creator's growth journey** by helping them complete challenges (e.g., by commenting or sending Gifts).

# Voice & Tone

## Voice

Our voice is **empowering, straightforward, and supportive**. We act as a guide, providing creators with a clear path to follow and celebrating their progress along the way. We are encouraging, not demanding. Our language is simple, scannable, and focused on action and reward.

**See TikTok Style Guide for platform-wide voice principles.**

## Tone

Our tone adapts to the creator's context, from informative countdowns to celebratory milestones.

| Tone | Informative | Helpful | Empathetic | Inviting | Celebratory |
|------|-------------|---------|------------|----------|-------------|
| **When to use** | Displaying factual information like countdowns, rules, or empty states. | Guiding users through challenges or explaining how a reward works. | Acknowledging a near-miss or a challenge that is about to expire. | Introducing a new season or encouraging users to start their journey. | Congratulating users on reaching a new stage, completing a challenge, or claiming a reward. |
| **Example in Journey** | Season overview (Season title, 7 days countdown, Season rewards, Week 1 tasks like "Be in a 4-person multi-guest LIVE 1 times", "Collect 2 Diamonds" 2/2) | Flare card description (Your rewards page, Tier 1 flare — "Attracts more viewers when you're LIVE", valid until June 3, 2025 1:00 PM) | Inbox notification (System notification "LIVE - Notices: Unlock rewards before time runs out!" — weekly challenges reset in LIVE Journey, go LIVE before 14:00 to claim) | Season poster (LIVE Journey 3 "Golden Harvest" — autumn forest scene, "Reap the bounty of your journey and claim your autumn riches!", CTA "Let's harvest") | Stage 60 max level (celebratory screen with a woman playing guitar, "max-level" state) |

## Challenge Text Patterns (from UXW All-in-one | LIVE Journey)

> **Color legend:** **blue** = placeholder; **orange** = filled value

### Single placeholder — count / duration

Most common pattern; the number scales with stage difficulty.

| Pattern | Filled example |
|---------|----------------|
| `Go LIVE for a total of {s_num} minutes` | Go LIVE for a total of 120 minutes |
| `Go LIVE on {s_num} separate days` | Go LIVE on 2 separate days |
| `Go LIVE on {s_num} days in a row` | Go LIVE on 2 days in a row |
| `Collect {s_num} Diamonds` | Collect 1 Diamond |
| `Get {s_num} new followers during LIVE` | Get 3 new followers during LIVE |

**Watch out:** singular vs plural ("1 Diamond" / "2 Diamonds", "1 new follower" / "3 new followers"). Always localize both forms.

### Two-variable patterns

`{gift} × {s_num}`, `{s_num1}/{s_num2}`, `{s_time1}—{s_time2}`

| Pattern | Filled example |
|---------|----------------|
| `{gift}×{s_num} sent in your LIVE` | Rose×30 sent in your LIVE |
| `Go LIVE within {s_num1} minutes after posting a video` | Go LIVE within 30 minutes after posting a video |
| `Receive {s_num} LIVE comments with {emoji} in it` | Receive 1 LIVE comment with heart in it |
| `Reach Top {s_num} in {s_ranking}` | Reach Top 99 in Daily Ranking |

**Watch out:** each variable needs an independent singular/plural switch. `{s_ranking}` is itself an enum — see "Daily / Weekly / Hourly Ranking" sub-strings.

### Compound count — base sentence + `{s_string}` appendix

Per-session × N-times

| Pattern | Filled example |
|---------|----------------|
| `Go LIVE for {s_num} minutes {s_string}` where `{s_string}` = `{s_num} times` | Go LIVE for 30 minutes 3 times |
| `Receive {s_num} comments {s_string}` where `{s_string}` = `in each of {s_num} LIVE videos` | Receive 12 comments in each of 2 LIVE videos |
| `Get {s_num} new followers {s_string}` where `{s_string}` = `in each of {s_num} LIVE streams` | Get 1 new follower in each of 2 LIVE sessions |
| `Participate in a {s_num}-person multi-guest LIVE {s_string}` | Participate in a 9-person multi-guest LIVE 2 times |

**Watch out:** the appended `{s_string}` is a separate Starling key (e.g. `ttlive_liveJourney2_challenge_pluralCount1`). Don't hardcode "times" in the base sentence — the unit varies (*times / LIVE videos / LIVE streams / LIVE sessions*).

### Time and date placeholders

| Placeholder | Format | Example |
|-------------|--------|---------|
| `{s_time1}—{s_time2}` | 24-hour clock | 14:00—23:00 |
| `{s_date}` | Specific date, **no year** | Go LIVE on Nov. 12 |
| `{s_day}` | Day of week, `ddd` | Go LIVE on Friday |
| `{s_countdown}` | 2d 23h 59m | Time left: 2d 23h 59m |

### Feature names — quote & case-sensitive

| Pattern | Note |
|---------|------|
| `Use "About me" in LIVE` | Quote the feature name as it appears in product. |
| `Create {s_num} LIVE Events and go LIVE on time` | "LIVE Events" is a product noun — title-case both words. |

# Microcopy sheet summary

This table summarizes high-usage, standardized phrasing for key actions and concepts.

| Phrasing/Term | Notes |
|---------------|-------|
| **LIVE Journey** | The official, capitalized feature name. |
| **Stage {s_num}** | The primary term for progression. Avoid "level." |
| **points** | The unit of progression. Avoid "experience" or "XP." |
| **challenges** | The collective term for weekly and milestone tasks. |
| **Season {s_num}** | Used for seasonal branding and titles (e.g., `S2`). |
| **Time left: {s_countdown}** / **Next update: {s_time}** | Standard formats for countdowns. `{s_countdown}` is for relative time (`2d 3h`), `{s_time}` is for a specific timestamp. |
| **{s_reward}** | Placeholder for reward names (e.g., `Flare`, `Promote coupon`). Should be paired with a quantity, e.g., `{s_reward}×{s_num}`. |
| **Claim** / **Claim all** | Primary CTAs for obtaining earned rewards. |
| **View all** | Standard CTA for navigating to a list or detailed view. |
| **No rewards yet** / **No points yet** | Empty state titles should be direct but encouraging. Pair with a helpful subtitle like `Complete challenges to get points!` |
| **Currency** | LIVE Journey does not currently involve direct cash rewards, so no currency placeholders are used. Avoid hardcoding any currency symbols. |
| **Gift Names** | Must be populated via server keys (e.g., `live_gift_5655` for "Rose") to ensure they are always up-to-date and localized correctly. |

# Legal & Compliance standards

| Do | Don't |
|----|-------|
| Use neutral, encouraging framing like **"Stage"** and **"points"** to denote progress. | Do not use evaluative terms like **"level," "rank,"** or **"experience,"** which could imply a judgment of a creator's quality or status. |
| When describing Gift-related challenges, phrase the action as viewers sending Gifts **"to your LIVE"** or **"to your LIVE content."** | Do not imply that Gifts are sent directly **"from viewers to you (the creator)."** The focus should be on the content. |
| Frame rewards as neutral tools and perks (e.g., "Flares attract more viewers," "Stickers decorate your LIVE"). | Do not over-promise the impact of rewards or frame them as guaranteed performance boosters. |
| Use abstract or universally positive seasonal themes like "Wonder Spark" or "Sprouting Spring." | Avoid tying seasonal copy to specific, culturally sensitive holidays unless cleared for all target regions. Be mindful of Northern/Southern hemisphere differences for seasons like Spring/Autumn. |

# L10N <> CD/PW // TikTok Placeholder Standardization

## Objectives // 目标

- Implement the standardized placeholder format on Starling for all strings on Client, Server, and Front End, including core product and LIVE. // 在 Starling 平台使用统一格式的占位符，无需根据客户端、前端和后端区分占位符格式。
- Starling analyzes and converts the placeholders into the required formats when strings are extracted from i18nops to codebase (Client). Starling provides solid conversion solutions to front-end and back-end in terms of incompatibility with the format in coding. // Starling i18nops 自动将统一格式转换为"客户端"规范格式。Starling 团队根据业务情况为"前端"和"后端"提供转换意见和方案。
- **New strings** only. Legacy strings will remain the same and will not be impacted. // 只适用于新增文案，存量文案不动。

## Writing guide // 占位符写作规范

> **General placeholder writing rules:** **{s_descriptiveWords}**

### Fundamentals

- Start and end with **single curly brackets** "{ }"
- For normal string, inside the brackets, start with the **s in lowercase**
  - (s = string)
- Follow the identifier with **descriptive words in camelCase**
  - **Descriptive words are defined by Content Designer/Content Writer.** They should be clear and meaningful to help linguists grasp what the variable stands for
- If there is more than one placeholder, use **different descriptive words to distinguish** them
- Inside curly brackets, no spaces or punctuation except for **an underscore ("_")**

### Examples

| Category | Identifier | Placeholder format on Starling | Example |
|----------|------------|-------------------------------|---------|
| **String** (general string, dates, time, big numbers in compact format e.g. 1k, 100k) | **s** | 1. {s_termsOfService}, {s_privacyPolicy}<br>2. {s_expireDate}<br><br>Multiple placeholders:<br>1. {s_hamburgerIcon}, {s_shareIcon} | 1. By continuing, you agree to our {s_termsOfService} and acknowledge that you have read our {s_privacyPolicy}<br>2. Links expired on {s_expireDate}<br>3. To add the Inbox shortcut, tap {s_hamburgerIcon} > {s_shareIcon} > Add to Home Screen. |
| **Number (Pluralization)** (integer, big numbers in compact format e.g. 1k, 100k) | **s** | 1. {s_num}<br>2. {s_postCount} | 1. One: {s_num} message request / Other: {s_num} message requests<br>2. One: {s_postCount} post / Other: {s_postCount} posts |
| **Number (non-pluralization)** (integer, plain number) | **s** | 1. {s_clipCount}<br>2. {s_discountPercentage}<br>3. {s_hour}, {s_min} | 1. Confirm ({s_clipCount})<br>2. -{s_discountPercentage}%% (*It's mandatory to use double %% to escape special characters for iOS & Android*)<br>3. You've reached your daily screen time today ({s_hour}h {s_min}m). (*Multiple s placeholders*) |
| **Floating number** (decimal digits) | **s** | 1. {s_cashAmount}<br>2. {s_videoDuration} | 1. Balance: {s_currencySymbol} {s_cashAmount}<br>2. {s_videoDuration}s (1.5s, 2.3s all use the same placeholders.) |

# How to use Starling (for Content Design)

> *This document complements the TikTok LIVE CD onboarding process by providing new team members with a go-to resource for mastering Starling in their daily tasks. Last update: Sept 9, 2025*

## Quick tutorial

Here's a walkthrough of how to release strings in Starling, our internal CMS tool.

- **00:02** - Create a Starling task
- **00:19** - Add strings separately
- **00:29** - Import strings via Feishu sheets (or Lark sheets)
- **00:58** - Add screenshots to strings separately
- **01:08** - Bulk-add screenshots to strings
- **01:48** - Urgent manual string releases
- **02:02** - Migrate strings

---

## Step-by-step breakdown

### Get Starling access

Reach out to the Admin of Starling projects and apply for access. Projects that we use at TikTok LIVE (ordered by frequency of use):

- **live_client**: one of the main projects used by LIVE CDs, e.g. inbox push notifications, playbooks, creator tips, etc. Sidenote: Sometimes we get requests from RD to release keys to **ugc-android / TikTok_Live**, which is the equivalent of the **live_client / ios and android** spaces on the CD side.
- **TikTok_LIVE_FE**: one of the main projects used by LIVE CDs, e.g. FAQ campaign pages, LIVE Studio keys, etc.
- **TikTok_Client**: used when a request overlaps with TikTok short video verticals
- **Live_campaign**: used for promotional campaigns, etc.
- **FE_i18n**: platform governance UIs, etc.
- **LIVE_Platform**
- **TikTok_Main**

---

### Uploading strings

Once you have access to Starling, you can start uploading strings. **Note:** Remember to always add new strings to a task, instead of a space. Strings directly added into spaces won't get translated.

**1.)** Your PM partner will share the Starling project(s) and space(s) they need the strings to be released in. If they don't know yet, ask them to confirm with the R&D partners working on the project, or to connect you with the R&D contact to check with them directly.

**2.)** Find the project in Starling, go into the **'Translation task'** tab, and select **'Task View'**.

**3.)** Create a new translation task by clicking on the **'+ Add Task'** button. Name the task, select the Starling space(s) you want the strings released to, and enter the project's Meego URL.

- Remember to fill in 4 fields:
  - **Name** of the project
  - **Sync spaces** (this needs to be confirmed with RD)
  - **Meego URL**
  - **Category** (the content category)

**4.)** Now you can start adding strings to the task. Add them manually, or bulk-import keys through a **Lark sheet** (highly recommended) – click the **'Import'** button and download a Lark template, fill in the keys/source/context/screenshots, then paste the link to the task to import it. Alternatively, there's also a **'Local file import'** option where you can download the sheet to your computer, convert the sheet to an Excel file, then upload it to Starling.

- For how to name tasks and keys, see #6 and #7 in **TikTok CD&PW // Key Syntax Standards** (doc: doxusi04jogJPVkvP9uiaYynqWf); for guidance on the preferred key prefixes for each Starling project, see #4 in **CDO // TikTok UI Text Localization Process and Guidelines** (wiki: wikcnrpq0ZA9aaabBgVF3gOm2Le)
- For how to add context and screenshots for linguists, see #3 in **TikTok Localization Guidelines** (wiki: wikcnfyYRybEo8hvm2vjMOBGkBa)
- For when and how to enable pluralization, see #9 in **TikTok Localization Guidelines** (wiki: wikcnfyYRybEo8hvm2vjMOBGkBa). For more pluralization tips: **LIVE multilingual pluralization** (doc: QHR8dPFXkoLWT9x0CYMlopnugRf)

**5.)** Once you've uploaded your sheet, you'll see verification results that will tell you if there are any **invalid keys**. You can download the verification file to see the reason. Invalid keys could be duplicates, or contain an extra space or an incorrect punctuation mark, etc.

**6.)** All keys added to the task are automatically released between 10:00 am-8:00 pm and sent for translation on Wednesdays and Fridays of each week.

**Note the 3:00 PM cut-off time**: be sure to release your keys before 3:00 PM on Wednesday, for example, in order to get translations back by EOB next Wednesday.

### Non-standard requests

#### Early key upload requests

- Content Designers may get occasional requests from PM partners to upload strings using placeholder draft copy so the R&D team can start testing their code. CDs can manually release the US-en strings, but make sure to **'Lock'** your task until it's ready for translation.
- To manually release keys, select the keys you want released, and click **'Release'**. You'll be directed to a page where you can select the release environment (most projects are released to the 'Official environment' or 'Formal environment' by default, unless otherwise requested by R&D) and the spaces they need to be released in. **Select all** spaces, and click **'Next'** to finish releasing them.

#### Specific language requests

- If only a few languages are needed, instead of all 55 languages, the CD can check the "**Customize target language**" box when creating the Starling task and select the languages you need.
- The keys will be automatically released during the scheduled localization cut-off times.
- **Note: If the project is likely to need more languages later, it's best to go with the standard process** and request all 55 languages from the start. This will prevent LPMs from having to manually resubmit the request later on.

#### Rush requests for localization

- For high-priority projects that need an urgent turnaround (ahead of the scheduled Wednesday/Friday automatic release days), CDs can flag the upcoming request to your localization partner ASAP to lock down vendor resources. Then ask the PM to submit this form and select **'Need Rush Turnaround'**.
- PMs should explain the reason for expediting the request and their expected deadline. All submitted keys need to be reviewed and finalized by CD.
- **SLA:** L10n will estimate a reasonable ETA, based on the key volume and complexity of the request (each request is limited to 2000 characters or less). The standard turnaround time for L10n is **5 business days** to complete translations.

#### Key migration requests

- Product or R&D teams may also ask for existing keys or tasks to be synced to another project in Starling. CDs can:
  - **1.) Create a new task** in the new destination project.
  - **2.)** Go to the old task and **select the keys that will need to be migrated**.
  - **3.)** Then **click "Migrate to destination projects"** and select the project and task you want them added to, and confirm migration.
  - **4.)** Go to the new task in the destination project, and **release the keys**.
- **Important:** Updates made to the source copy or translations are not synced to the new project automatically. **Do remember to migrate the keys again** if any changes are made later.
- Other notes about migration:
  - **Helpful when more than 1 Starling project is requested**: Sometimes RD may ask for the same set of keys for a requirement to be released to another Starling project. Follow the steps above to migrate your first task to the second task. Just **remember to lock the second task** (so only one of your tasks is automatically sent for translation), and return to it the next week to migrate and release the translations.
  - **Post-migration changes**: It is okay to add keys to a task that has been migrated. Any new keys released will be automatically translated together with the next batch of localization requests, as usual.

#### Syncing spaces in the same project

- If Product or RD requests that an existing key be released to another space in **the same Starling project, it won't need to be migrated**. A new space can be added to the original task.
- Find the original task the key was uploaded to > Tap the "..." settings icon in the top-right corner > Tap "Editing task" > Choose the new space you need to add it to "Synchronous Space" > Release all of the strings (including their translations).

#### Existing key updates

- Generally, opt to create a new key instead of updating an existing key, unless PMs and RD have confirmed that it will not impact UIs currently using the key, or when it is necessary for content quality or product iterations.
- **Do not update** if the ask is to **change the placeholder** within an existing key. This change in placeholder logic will likely lead to issues online. For asks to change placeholders, create a new task and release a new key instead.
- For existing keys that are updated, check with the PM and Localization to see if they need to be immediately translated. If not, the keys will be automatically sent for translation as scheduled.
